# go-confluence-mcp

Локальный MCP-сервер гибридного поиска по кодовой базе Go и документации
(выгрузки Confluence в `.md`/`.txt`) для Claude Code.

Полностью офлайн и бесплатно: эмбеддинги считаются локально на CPU, никакие
данные никуда не отправляются. Модель скачивается один раз при установке.

## Как устроено

| Слой | Реализация |
|------|------------|
| Эмбеддинги | `sentence-transformers/all-MiniLM-L6-v2`, CPU/PyTorch, 384 измерения |
| Векторный поиск | ChromaDB `PersistentClient`, cosine space, векторы передаются явно |
| Лексический поиск | `rank_bm25.BM25Okapi`, состояние сохраняется через `pickle` |
| Слияние | Reciprocal Rank Fusion, `score = Σ 1 / (60 + rank)` |
| Протокол | официальный Python SDK `mcp`, low-level `Server` + stdio |

Векторный поиск ловит смысл («как считается НДС»), BM25 — точные совпадения
имён (`CalculateVAT`, `ErrInvoiceNotFound`, ключи конфигов). RRF объединяет два
ранжирования, не требуя приводить несопоставимые шкалы оценок к общему виду.

### Нарезка на чанки

* **`.go`** — специализированный сплиттер. Один чанк ≈ одно объявление верхнего
  уровня (`func`, метод, `struct`, `interface`) вместе с его doc-комментарием.
  `package`, `import`, одиночные `const`/`var` склеиваются в общую «шапку».
  Баланс скобок считается с учётом комментариев, строковых и рунных литералов
  и raw-строк в обратных кавычках — `func f() string { return "}" }` индекс не ломает.
* **`.md`/`.markdown`** — документ режется по заголовкам, затем каждая секция —
  recursive character splitting. К чанку приклеиваются «хлебные крошки»
  заголовков (`Биллинг > Расчёт НДС`). Заголовки внутри ``` ``` ```-блоков игнорируются.
* **`.txt`** — recursive character splitting.

В каждый чанк дописывается шапка с путём к файлу, пакетом и именем символа —
это попадает и в вектор, и в BM25, заметно поднимая точность.

### Инкрементальность

Для каждого файла хранятся MD5 и SHA256 (`data/manifest.json`). При повторном
вызове `index_directory` неизменившиеся файлы пропускаются, изменившиеся
переиндексируются с удалением старых чанков, исчезнувшие — вычищаются из базы.
Перезагрузка Mac или перезапуск Claude Code не приводят к переиндексации.

## Установка

```bash
git clone <этот-репозиторий> && cd mcp-vector-search
./install.sh
```

Скрипт сам: найдёт Python 3.10+, создаст `~/.local/share/go-confluence-mcp/`,
развернёт venv, поставит зависимости, заранее скачает модель, прогонит сквозную
самопроверку и пропишет сервер в `~/.claude.json` (со свежим бэкапом).

Занимает ~2.5 ГБ на диске и несколько минут на первый запуск (в основном torch).

Флаги:

| Флаг | Смысл |
|------|-------|
| `--reinstall` | пересоздать venv с нуля |
| `--skip-claude-config` | не трогать `~/.claude.json` |
| `--skip-selftest` | пропустить самопроверку |
| `--dir PATH` | другой каталог установки |
| `--name NAME` | другое имя сервера в конфиге |

> Если Claude Code был открыт во время установки — перезапустите его: он
> перезаписывает `~/.claude.json` при выходе.

## Использование

```bash
cd ~/work/мой-go-сервис
claude
```

В первой сессии попросите проиндексировать источники:

```
> проиндексируй текущий каталог через index_directory
> проиндексируй ~/Documents/confluence-export через index_directory
```

Дальше просто задавайте вопросы — Claude сам вызовет `search_knowledge_base`.

## Инструменты MCP

### `index_directory(path: str)`

Рекурсивно индексирует каталог. Служебные директории (`.git`, `vendor`,
`node_modules`, `venv`, `dist`, …) и файлы больше 2 МБ пропускаются.
Возвращает отчёт: сколько файлов новых, изменённых, неизменившихся и удалённых,
сколько чанков добавлено и удалено, сколько всего в индексе.

### `search_knowledge_base(query: str, top_k: int = 5)`

Гибридный поиск. Для каждого результата возвращает тип источника
(`Code` — Go, `Confluence` — документация), путь к файлу, имя символа или
цепочку заголовков, RRF-оценку с разбивкой по подсистемам и сам фрагмент.
`top_k` ограничен диапазоном 1..50.

### `clear_index()`

Удаляет коллекцию ChromaDB, состояние BM25 и кэш хэшей; каталог данных
очищается и пересоздаётся. Нужен при смене модели эмбеддингов или для сборки
базы с нуля.

## Раскладка на диске

```
~/.local/share/go-confluence-mcp/
├── hybrid_knowledge_mcp.py   сервер
├── requirements.txt          зафиксированные зависимости
├── claude_mcp_config.json    готовый фрагмент конфига
├── venv/                     виртуальное окружение
├── models/                   HF_HOME, здесь лежит MiniLM
└── data/
    ├── chroma/               persistent-хранилище ChromaDB
    ├── bm25.pkl              состояние BM25
    └── manifest.json         кэш хэшей MD5+SHA256 и id чанков
```

## Диагностика

```bash
# сервер виден Claude Code?
claude mcp list

# сквозная проверка на временных данных, реальный индекс не трогается
~/.local/share/go-confluence-mcp/venv/bin/python \
    ~/.local/share/go-confluence-mcp/hybrid_knowledge_mcp.py --selftest
```

Логи сервера идут строго в `stderr` — stdout зарезервирован под JSON-RPC.
Более того, при старте fd 1 перенаправляется в stderr, а «настоящий» stdout
отдаётся только транспорту MCP: посторонний `print` из зависимости не сломает
протокол. Уровень логирования — `GO_CONFLUENCE_MCP_LOG_LEVEL=DEBUG`.

Если индекс собирался другой моделью эмбеддингов, сервер откажется мешать
векторы разной размерности и попросит вызвать `clear_index()`.
